Circom -> Verifiers (v1-mainnet)

    Two circuits:

        circuits/transfer_proof.circom   -> contracts/TransferVerifier.sol   (10 public inputs)
        circuits/withdraw_proof.circom   -> contracts/WithdrawVerifier.sol   (11 public inputs)

    Shared code:

        circuits/spend_core.circom       SpendCore — everything both circuits prove
        circuits/note_lib.circom         OwnerKeys, NoteCommitment, NoteNullifier
        circuits/merkle_path.circom      Merkle inclusion
        circuits/range_check.circom      0 <= x < 2^bits

    There is no deposit circuit any more (see zk_proof_deposit.txt).

    Artifacts go to build/v1m/ so the V1 demo's files in build/ stay untouched.


STEP 1 — Tools (once)

    circom 2.1+          https://docs.circom.io/getting-started/installation/
    npm install          (snarkjs, circomlib come from package.json)

        circom --version
        npx snarkjs --version


STEP 2 — Powers of Tau (once)

    Phase 1 is the public Hermez ceremony. The circuits are ~27k constraints,
    so the 2^17 file is more than enough.

        mkdir -p ptau
        curl -L https://storage.googleapis.com/zkevm/ptau/powersOfTau28_hez_final_17.ptau \
             -o ptau/powersOfTau28_hez_final_17.ptau


STEP 3 — Build everything

        bash scripts/build_circuits.sh            both circuits
        bash scripts/build_circuits.sh transfer   just one

    For each circuit the script runs:

        circom circuits/<name>_proof.circom --O2 --r1cs --wasm --sym -o build/v1m
            --O2 removes every linear constraint (~60k -> ~27k): faster proving

        snarkjs groth16 setup   build/v1m/<name>_proof.r1cs ptau/... build/v1m/<name>_proof_0000.zkey
        snarkjs zkey contribute build/v1m/<name>_proof_0000.zkey build/v1m/<name>_proof_final.zkey
        snarkjs zkey export verificationkey  ... build/v1m/<name>_verification_key.json
        snarkjs zkey export solidityverifier ... contracts/<Name>Verifier.sol

    and renames the generated contract (snarkjs calls it Groth16Verifier).

    Outputs:

        build/v1m/transfer_proof_js/transfer_proof.wasm     witness generator (wallet)
        build/v1m/transfer_proof_final.zkey                 proving key (wallet), ~18 MB
        build/v1m/transfer_verification_key.json            off-chain verify (relayer)
        contracts/TransferVerifier.sol                      on-chain verify
        (same for withdraw)


STEP 4 — Compile and test

        npx hardhat compile
        npx hardhat test                                   in-process network

    or against a local node:

        npx hardhat node                                   (another shell)
        npx hardhat run scripts/deploy.js --network localhost
        npx hardhat test --network localhost


!! STEP 3 IS A DEVELOPMENT SETUP ONLY !!

    The phase-2 step above is ONE local contribution. Whoever ran it could
    have kept the randomness ("toxic waste") and could forge proofs, i.e.
    mint notes and drain the pool.

    Before mainnet, run a multi-party phase-2 ceremony on these two circuits:

        - several independent contributors (team + outside people), each
          running `snarkjs zkey contribute` on the previous file
          (or a coordinated tool such as p0tion)
        - finish with `snarkjs zkey beacon` using a public future block hash
        - publish the transcript; anyone can check it with `snarkjs zkey verify`

    The setup is secure as long as ONE contributor destroyed their randomness.
    Changing a circuit means a new ceremony and new verifier contracts.


Circuit changes that need a rebuild + redeploy

    Anything in circuits/ — including the domain separators in note_lib.circom,
    which must also match helpers/constants.js and NoidPool.sol (D_CM).
    Tree depth changes also need scripts/gen_zeros.js re-run.
