Withdraw Proof (v1-mainnet)

    circuits/withdraw_proof.circom   -> Withdraw(4 inputs, 2 outputs, depth 20)
    circuits/spend_core.circom       -> SpendCore, shared with transfer

    ~26.3k constraints (compiled with --O2)

Purpose
- Spends up to 4 private notes of ONE token.
- Releases a public amount of that token out of the pool.
- Creates 2 private notes of the same token:
    - change (back to the sender)
    - relayer fee
- Prevents double spending with nullifiers.

Ownership, input notes, nullifiers, output notes and the 128-bit range
checks are exactly the transfer circuit's (same SpendCore template):
see zk_proof_transfer.txt. Only the differences are listed here.


Public Inputs (11) — order matches NoidPool._withdrawSignals

    0      root
    1-4    nullifiers[4]
    5-6    outCommitments[2]     change, relayer fee
    7      relayer               the relayer's user commitment
    8      publicToken           uint160(token address) — the token leaving
    9      publicAmount          the amount leaving
    10     extDataHash           hash of recipient, unwrapNative, encrypted
                                 outputs, outgoing record, chain id, pool


Token
- The contract must know what to send, so the token is public here.
- The circuit uses publicToken AS the token of every input and output:

        token = publicToken

  so a proof can only release the token its notes actually hold.


Amount
- RangeCheck(128)(publicAmount)


Conservation Constraint

        sum(inAmounts) === sum(outAmounts) + publicAmount

Ensures:
- the value released plus the change and fee equals the value spent
- nothing created, nothing destroyed


Recipient
- Not a circuit signal. It is part of the withdraw ext data, and the
  contract recomputes extDataHash from the ext data it receives:

        extDataHash = keccak(chainId, pool, "menoid.v1m.withdraw",
                             recipient, unwrapNative, encryptedOutputs,
                             outgoingRecord) mod p

- A relayer that changes the recipient changes the hash, and the proof
  fails. The same holds for unwrapNative and the ciphertexts.

        extDataSquare <== extDataHash * extDataHash
        (keeps the hash inside a constraint)


Relayer Binding
- outOwners[1] === relayer        the fee note belongs to the relayer


What the contract adds
- 0 < amount <= 2^128 - 1, token and recipient non-zero
- unwrapNative only for the wrapped native token
- root among the last 100, nullifiers unspent and pairwise different
- funds sent only after every state change (non-reentrant)


Swaps (next step) will reuse this circuit unchanged: "an amount of a token
leaves the private balance" is the same statement; only where the value goes
(an address vs. a swap adapter) differs, and that goes in the ext data.
