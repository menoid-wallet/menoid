Transfer Proof (v1-mainnet)

    circuits/transfer_proof.circom   -> Transfer(4 inputs, 3 outputs, depth 20)
    circuits/spend_core.circom       -> SpendCore, shared with withdraw
    circuits/note_lib.circom         -> OwnerKeys, NoteCommitment, NoteNullifier

    ~26.9k constraints (compiled with --O2)

Core Logic:
- The circuit proves that:
    - the sender knows the spending key of the identity every input is locked to
    - every real input note exists in the Merkle tree
    - every nullifier is correctly derived
    - every output note is correctly constructed
    - all inputs and outputs are the SAME token, and that token stays private
    - total input value equals total output value
    - the last output belongs to the relayer

--------------------------------------------------
Domain Separators:
--------------------------------------------------

    1  user commitment     Poseidon(1, address, spendPk.x, spendPk.y)
    2  nullifier key       Poseidon(2, sk)
    3  note public key     Poseidon(3, ownerUc, randomness)
    4  note commitment     Poseidon(4, token, amount, npk)
    5  nullifier           Poseidon(5, nk, commitment, randomness)

    Each hash starts with its own number, so one can never be mistaken for
    another. Must match helpers/constants.js and NoidPool.sol (D_CM = 4).

--------------------------------------------------
Public Inputs (10) — order matches NoidPool._transferSignals:
--------------------------------------------------

    0      root               a recent root of the tree the inputs are in
    1-4    nullifiers[4]      one per input slot (dummies included)
    5-7    outCommitments[3]  receiver, change, relayer fee
    8      relayer            the relayer's user commitment
    9      extDataHash        hash of the encrypted outputs + outgoing record
                              + chain id + pool address

    No token, no amount, no flags.

--------------------------------------------------
Private Inputs:
--------------------------------------------------

Ownership:
- sk             spending key (BabyJubJub)
- ownerAddress   the sender's real wallet address

Token:
- token          uint160(token address) — one value used by every note

Input notes (x4):
- inAmounts[i]
- inRandomness[i]
- inPathElements[i][20], inPathIndices[i][20]   Merkle path

Output notes (x3):
- outAmounts[j]
- outRandomness[j]
- outOwners[j]    receiver user commitments

--------------------------------------------------
Ownership:
--------------------------------------------------

    spendPk        = BabyPbk(sk)                                 sk · Base8
    userCommitment = Poseidon(1, ownerAddress, spendPk.x, spendPk.y)
    nk             = Poseidon(2, sk)

Meaning:
- Every input below is rebuilt with THIS userCommitment. Knowing someone's
  address is not enough; you need their sk.
- nk is computed from sk inside the circuit. A viewer who was given nk can
  compute nullifiers but cannot produce this proof.

--------------------------------------------------
Input Notes (per slot i):
--------------------------------------------------

    RangeCheck(128)(inAmounts[i])                        0 <= amount < 2^128

    npk        = Poseidon(3, userCommitment, inRandomness[i])
    commitment = Poseidon(4, token, inAmounts[i], npk)

    nullifiers[i] === Poseidon(5, nk, commitment, inRandomness[i])

    isDummy = (inAmounts[i] == 0)
    (1 - isDummy) * (MerkleRoot(commitment, path) - root) === 0

Meaning:
- A real note (amount > 0) must be in the tree under `root`.
- A zero-value slot is a dummy: no Merkle check, but its nullifier is still
  computed and published, and looks like any other. On-chain you cannot tell
  how many notes were really spent.
- The token is part of the commitment, so a note can only be spent as the
  token it was created with.

--------------------------------------------------
Output Notes (per slot j):
--------------------------------------------------

    RangeCheck(128)(outAmounts[j])
    outCommitments[j] === Poseidon(4, token, outAmounts[j],
                                   Poseidon(3, outOwners[j], outRandomness[j]))

    outOwners[2] === relayer

Meaning:
- Every output is the same token as the inputs (same `token` signal).
- Unused outputs are zero-value notes; there are always 3.
- Slot 2 is always the relayer's fee note (it can be worth 0).

--------------------------------------------------
Balance Constraint:
--------------------------------------------------

    sum(inAmounts) === sum(outAmounts)

Meaning:
- No value created or destroyed.
- Range checks keep every amount below 2^128, so the sums stay far below the
  field prime and cannot wrap around to "balance" a forged amount.

--------------------------------------------------
External Data:
--------------------------------------------------

    extDataSquare <== extDataHash * extDataHash

Meaning:
- extDataHash is a public input the contract computes itself from the
  ciphertexts and outgoing record it receives. The square keeps it inside a
  constraint so the proof is bound to it.
- Change one ciphertext -> different hash -> the proof does not verify.

--------------------------------------------------
What the contract adds:
--------------------------------------------------

- root must be one of the tree's last 100 roots
- nullifiers unspent and pairwise different (the circuit does not check
  distinctness: the same note in two slots would be counted twice)
- output commitments new and non-zero
